# Implementation Plan: GDeflate GPU Decompression

**Branch**: `009-gdeflate-gpu-decompression` | **Date**: 2026-03-01 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/009-gdeflate-gpu-decompression/spec.md`

## Summary

Replace the current LZ77-based GPU decompression with GDeflate — an open-standard GPU-optimized compression format that reformats DEFLATE streams for 32-way parallel decompression per 64KB tile. The HLSL reference decompressor from Microsoft's DirectStorage repository will be ported to WGSL for cross-platform wgpu support. The CPU-side compressor will produce GDeflate-formatted bitstreams. Backward compatibility with existing LZ77 (v1) files is maintained via format version routing. Target: >1 GB/s GPU decompression throughput (vs current ~130 MiB/s).

**Scale/Scope**: Operates on 64KB tiles with 32 sub-streams; files from KB to multi-GB

## Key Design Decisions

### D1: GDeflate Compressor Strategy

**Decision**: Implement a pure-Rust GDeflate compressor using `flate2` for DEFLATE encoding + custom sub-stream interleaving.

**Rationale**: The `gdeflate-rs` FFI wrapper would add a C++ build dependency, complicating cross-platform builds. Since GDeflate compression runs on CPU only, the approach is:
1. Use `flate2` (already an allowed dependency) to DEFLATE-encode each tile
2. Parse the DEFLATE bitstream and redistribute codes across 32 sub-streams per the GDeflate spec
3. Serialize the interleaved sub-streams into the GDeflate bitstream format

This avoids FFI complexity while leveraging `flate2`'s proven DEFLATE encoder.

### D2: WGSL Shader Architecture

**Decision**: Single WGSL shader file (`gdeflate_decompress.wgsl`) with workgroup size 32 (one wave per workgroup). Emulate all wave intrinsics via workgroup shared memory.

**Rationale**:
- Workgroup size 32 (not 512): Simpler dispatch model — one workgroup per tile. The reference HLSL uses 512 threads (16 waves) with work-stealing, but for our per-tile dispatch model, 32 threads/workgroup is sufficient and avoids the work-stealing complexity.
- Shared memory emulation: WGSL subgroup operations are an extension not universally supported. Using `var<workgroup>` + `workgroupBarrier()` works on all wgpu backends.
- 64-bit emulation: BitReader state as `(lo: u32, hi: u32)` pair with manual carry logic.

### D3: Dual Pipeline Architecture

**Decision**: `WgpuBackend` creates two compute pipelines at initialization — one for LZ77, one for GDeflate. The engine selects which to use based on `format_version`.

**Rationale**: The two shaders have fundamentally different bindings, workgroup sizes, and decode logic. Separate pipelines are cleaner than conditionalizing a single shader. Both pipelines share the same `wgpu::Device` (cached singleton).

### D4: Format Version Strategy

**Decision**: Bump file-level `FORMAT_VERSION` to 2 for GDeflate. Accept both 1 and 2 in `from_bytes()`. New compressions always produce v2.

**Rationale**: Clean separation. The format version field already exists in both header and footer. The tile header's `version` byte provides per-tile encoding identification.

## Implementation Phases

### Phase 1: Setup
- Add `flate2` dependency to `crush-gpu/Cargo.toml`
- Add format version constants (`FORMAT_VERSION_LZ77`, `FORMAT_VERSION_GDEFLATE`, `TILE_VERSION_LZ77`, `TILE_VERSION_GDEFLATE`)
- Update `GpuFileHeader::from_bytes()` and `GpuFileFooter::from_bytes()` to accept both v1 and v2

### Phase 2: Foundational — GDeflate CPU Codec
- Implement `gdeflate.rs`: `gdeflate_compress_tile()` and `gdeflate_decompress_tile()`
- GDeflate compressor: DEFLATE encode → parse bitstream → interleave across 32 sub-streams → serialize
- GDeflate decompressor (CPU fallback): deserialize → decode Huffman tables → decode LZ77 → de-interleave
- Unit tests for compress/decompress roundtrip

### Phase 3: User Story 1 — GPU Decompression Shader
- Port HLSL reference decompressor to `gdeflate_decompress.wgsl`
- Implement BitReader with 64-bit emulation
- Implement Huffman table building in workgroup shared memory
- Implement decode loop (block header → Huffman decode → LZ copy)
- Add `decompress_tiles_gdeflate()` to `ComputeBackend` trait
- Implement in `WgpuBackend`: create GDeflate pipeline, dispatch, readback
- Wire format version dispatch in `engine.rs`
- Roundtrip tests: compress (CPU) → decompress (GPU) → verify

### Phase 4: User Story 2 — Engine Integration
- Update `compress()` to produce GDeflate format (v2 headers, GDeflate payloads)
- Update `decompress()` with format version dispatch logic
- CPU fallback path for GDeflate decompression
- Update `decompress_tile_by_index()` for random access with GDeflate
- Full roundtrip tests with GPU and CPU paths

### Phase 5: User Story 3 — Backward Compatibility
- Create test fixtures: compress data with current v1 (LZ77) format, save as test artifacts
- Ensure v1 files decompress correctly with updated code
- Add backward compatibility test suite
- Verify mixed-version scenario (old files + new files in same session)

### Phase 6: User Story 4 — Benchmarks
- Update `throughput.rs`: add GDeflate GPU and CPU benchmark groups
- Update `ratio.rs`: add GDeflate compression ratio benchmarks
- Add LZ77 vs GDeflate comparison groups
- Run benchmarks, document results

### Phase 7: Polish & Cleanup
- Code duplication analysis (jscpd)
- Documentation review
- Quality gate verification (clippy, fmt, doc, tests)
